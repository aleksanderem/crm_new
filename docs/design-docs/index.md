# Design Docs Index

This directory holds durable design reasoning for the repository.

Start with `core-beliefs.md` for the cross-cutting beliefs that should remain stable even as implementations change.

Then use focused design docs for larger architectural or workflow decisions. Existing materials under `docs/plans/` and standalone docs in `docs/` should be linked or gradually migrated here when they contain durable rationale rather than one-off execution steps.

Current high-value inputs to migrate or reference over time include the modular platform architecture notes, the document template system design, and the SMS confirmation pilot rules and retrospectives.
