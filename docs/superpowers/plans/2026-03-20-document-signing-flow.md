## Phase 6: Auto-generation branch for TipTap documents

File: convex/gabinet/_helpers/autoGenerateDocuments.ts

Current behavior: for every requiredFormTemplate, creates formDocument with
responseData = prefilledData, status = pending_signature (if sig required) or draft.

Change: after fetching template, detect templateType === "document":

1. Extract form fields from template.contentJson via JSON tree walk (server-safe, no DOM)
2. Determine initial status:
   - Has form fields → "draft" (patient fills first, then signs)
   - No form fields → "pending_signature" (direct to signing)
3. For no-form-fields case: responseData stays as prefilledData (HTML rendered client-side
   on signing page, then stored at signature time)
4. Always generate signingToken (for both draft and pending_signature)
5. Schedule email for both — with different context (treatment name, appointment date)

Server-side form field extraction (no DOM needed):
```typescript
function extractFormFieldsFromJson(json: unknown): boolean {
  // Walk TipTap JSON tree, return true if any formField nodes found
  if (!json || typeof json !== "object") return false;
  const node = json as { type?: string; content?: unknown[] };
  if (node.type === "formField") return true;
  if (Array.isArray(node.content)) {
    return node.content.some((child) => extractFormFieldsFromJson(child));
  }
  return false;
}
```

## Phase 7a: Backend — signing mutations

File: convex/documents/documents.ts

### 1. Extend getBySigningToken

Accept both "draft" and "pending_signature" statuses:
```typescript
if (doc.status !== "pending_signature" && doc.status !== "draft")
  throw new Error("Document is not awaiting action");
```

### 2. New mutation: submitDocumentFormFields

Public (token-based, no auth). Handles form fill step for document-type templates:
```typescript
submitDocumentFormFields(token, renderedHtml, formFieldValues)
  → validates token + expiry + status === "draft"
  → stores responseData = JSON.stringify({ html: renderedHtml, formFieldValues })
  → transitions status: "draft" → "pending_signature"
```

HTML is rendered client-side (needs DOMParser), then sent to server for storage.

### 3. Extend recordSignature

Add optional resolvedHtml parameter. For document-type templates with no form fields,
the signing page renders HTML client-side and sends it along with the signature:
```typescript
recordSignature(token, signatureData, signedByName, ..., resolvedHtml?)
  → if resolvedHtml provided, update responseData = { html: resolvedHtml, formFieldValues: {} }
  → then record signature as before
```

## Phase 7b: Frontend — two-step signing page

File: src/routes/sign.form.$token.tsx

Detect template.templateType === "document" in SigningFlow component.

### Document-type with form fields (status = "draft"):

1. Parse template.contentJson → extract form fields
2. Show DocumentFormFiller component (reuse from generate dialog)
3. On submit:
   a. Client renders HTML via renderDocument(contentJson, prefilledData, fieldValues)
   b. Call submitDocumentFormFields(token, html, fieldValues)
   c. Status becomes "pending_signature"
   d. Advance to signing step

### Document-type, ready for signing (status = "pending_signature"):

1. Client renders HTML from contentJson + prefilledData (from responseData)
   OR reads responseData.html if already stored
2. Show rendered document in read-only viewer
3. Show acknowledgment checkbox + signature section
4. On sign: call recordSignature(token, signatureData, ..., resolvedHtml)

## Key design decisions

1. HTML rendering stays client-side (DOMParser not available in Convex runtime).
   Client renders HTML and sends it to server for storage.

2. No new schema fields on formDocuments. We reuse responseData:
   - For pdfme: responseData = JSON.stringify(surveyJsData)
   - For document: responseData = JSON.stringify({ html, formFieldValues })
   Both formats coexist.

3. Two-step signing for document-type with form fields:
   draft → (form fill) → pending_signature → (sign) → signed

4. One-step signing for document-type without form fields:
   pending_signature → (sign + store HTML) → signed

5. Backward compatible: pdfme flow is completely unchanged.
